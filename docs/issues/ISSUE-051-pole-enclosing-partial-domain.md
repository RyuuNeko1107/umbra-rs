# ISSUE-051: 極を囲む部分食域が地球を一周する多角形になる

## 背景（実測）

M9 残(3) (3g)（反子午線 MultiPolygon 分割）は、**跨ぎ回数が奇数＝経度の巻き数 ±1 ＝極を囲む**場合を
「分割せず元のリングを返す」としている（§11.8(d)）。弧が対を成さず子午線上で閉じられないためで、
**面積を失わず捏造もしない**という点では正しい退避だが、**出力そのものは不正**である。

実測（`standard_engine(bundled_time_data())`）:

| 日食 | 跨ぎ回数 | `partial_limit` | GeoJSON | 出力経度幅 |
|---|---|---|---|---|
| 2021-12-04（南極域・皆既） | **1（奇数）** | 2 環・330 頂点・lat [−67.9, −10.6] | `Polygon` | **358.5°** |
| 2024-04-08（北米・皆既） | 0 | 1 環・491 頂点 | `Polygon` | 251.7°（正常） |

2021-12-04 の外環は ±180 を 1 回だけ跨ぐので、**先頭と末尾を結ぶ辺が経度を逆走して地球をほぼ一周する**。
GeoJSON 消費側はこれを「地球を一周する帯」として描画する＝**もっともらしく見えて誤っている**。
同種の日食（2028-07-22・2037-07-13 は跨ぎ 3 回）も同じ。

## 問題の本質（スコープの確定）

**出力層だけの問題ではない。** `partial_limit` は `(lon, lat)` 平面で `union_rings` を解いて得るが、
平面の even-odd 判定・`pip`・shoelace は**経度が折り返す入力に対して意味を持たない**
（algorithms §11.7 の「残る近似」に既記）。したがって極を囲む日食では

1. **ユニオンの結果自体**が正しい保証がない（平面フレームの前提が破れている）。
2. その上で GeoJSON の閉じ方も不正（上記の一周する辺）。

の 2 段で壊れている。**(3g) の「分割しない」退避は 2 を回避していない**（不正な多角形を返している）。

## 設計上の要点（どこで極を決めるか）

極を囲むリングを GeoJSON で正しく表すには、**どちらの極が領域に含まれるか**を知る必要がある
（RFC 7946 の右手則で、極を含む多角形は子午線を極まで辿って閉じる）。しかし

- 巻き数 ±1 のリングは**平面 shoelace が意味を持たない**ので、リングの向きから内外を決められない。
- `union_rings` の環向き正規化（外環 CCW）も同じ理由で、跨ぐリングには効いていない。

⇒ **幾何層（umbra-geo）だけでは決定不能**。一方で **umbra-eclipse は領域の定義そのものを持っている**
（「その点が [P1,P4] のいずれかの時刻で閉半影内かつ昼面側か」）。よって

- **umbra-eclipse が極の所属を判定する**（極点 `lat=±90` について、サンプル時刻で半影内かを直接評価）。
- **umbra-geo は与えられた極で閉じる**（子午線を極まで辿り、極上で ±180 を渡り、戻る）。

という責務分割にする。これは (3f) で `union_rings` に自己交差入力を許容させたのと同じ方針
（幾何層は機構、天文的な意味づけは eclipse 層）。

## 目的

極を囲む部分食域について、**地球を一周する不正な多角形を返さない**。

## 非目的

- `union_rings` を球面幾何へ作り替えること（平面近似は accuracy §4.3 / conventions §12 の登録済み近似）。
- 反子午線を跨ぐが極を囲まない場合（(3g) で対応済み）。

## 検討した選択肢

| 案 | 内容 | 評価 |
|---|---|---|
| (i) **極で閉じる** | eclipse 層が極の所属を判定し、geo 層が子午線→極→子午線で閉じる | **本命**。RFC 7946 の標準的表現。上記 2 を解く。ただし 1（ユニオン自体の妥当性）は平面近似のまま残るので、精度は ballpark 据え置きと明記する |
| (ii) **経度原点を回す** | 領域が跨がない位置へ経度原点を回して union し、戻す | 極を囲む領域は**全経度に跨る**ので回しても解消しない。反子午線のみの場合には有効だが本件には無効 |
| (iii) **出力しない** | 極を囲む場合は `partial_limit` を `None`／GeoJSON feature を省く | 不正な図形は出さなくなるが、**利用者は理由を知れない**まま出力が消える。公開 API の後退でもある |

**決定（2026-09-15）**: **(i) 極で閉じる**を採る。理由:

- いま返しているのは「近似的に正しい図形」ではなく、**存在しない辺（経度を逆走して地球を一周する辺）を
  含む図形**である。(i) はその 1 本の偽の辺を消して、実在する境界（子午線と極）に置き換える。
  **これは近似の改善ではなく、捏造の除去**である。
- (iii)（出さない）は偽の辺は消えるが、**外周の情報そのものを失う**。部分食域の許容は ballpark
  （数十 km・algorithms §許容誤差）であり、平面ユニオンの誤差はその枠内に収まる見込みが高い。
  情報を捨てる根拠としては弱い。
- 残る不確かさ（ユニオン自体が平面フレームで解かれていること）は**新たに生じるものではなく既存**で、
  conventions §12 に登録済みの近似である。(i) はそれを悪化させない。

**ただし精度の表明は据え置く**: 極域では外周位置の保証を上げない。accuracy.md §4.3 に
「極を囲む場合はユニオンが平面フレームで解かれており、外周位置の誤差は ballpark よりさらに緩い」
ことを明記する（誤差を隠さない・conventions §11）。

## 確定仕様

1. **判定**: 外環の反子午線跨ぎ回数が**奇数**なら極を囲む（(3g) で実装済みの `antimeridian_crossings`）。
2. **どちらの極か＝umbra-eclipse が決める**。部分食域の定義（[P1,P4] のいずれかの時刻で閉半影内かつ
   昼面側）を**極点そのもの**に適用して判定する。両極とも属さない／両極とも属す場合は
   **閉じずに現状維持**（捏造しない）。
3. **閉じ方＝umbra-geo が実行する**。極 `P`（`lat = ±90`）を与えられたら、弧の端点から子午線
   `+180` / `−180` を `P` まで辿り、極上で渡り、戻って閉じる。挿入する頂点は
   `(±180, lat_end)`（既存の補間点）と `(±180, ±90)` のみで、**それ以外の点を作らない**。
4. **跨がない／偶数跨ぎの出力はバイト不変**（(3g) の回帰）。

## 受け入れテスト戦略

- 合成: 経度を 1 周する帯リング（跨ぎ 1 回・3 回）が、指定した極で閉じられ、**経度幅 360° の辺を持たない**・
  リングが閉じる・環向きが RFC 7946 準拠・極の頂点（`lat=±90`）を含むこと。
- 実 2021-12-04: GeoJSON の外環に**経度を逆走する一周辺が無い**こと、極の頂点を含むこと、
  中心線の全点を内包すること（(3f) の headline を極ケースでも維持）。
- 反子午線のみ（2016-03-09）と非跨ぎ（2024-04-08）の**出力がバイト不変**であること（回帰）。

## エンジン側の確定仕様（2026-09-15・geo 側実装後）

geo 側（`EnclosedPole` / `geojson_geometry_with_pole`）は実装済み。残りは**どちらの極かを決めて渡す**部分。

### 判定の定義（部分食域の定義をそのまま極点に適用する）

部分食域は「[P1,P4] のいずれかの時刻で**閉半影内かつ昼面側**にある地表点」。これを極点に適用する:

サンプル時刻 `t` ごとに、極点（測地緯度 `±90`・経度は任意＝極は自転軸上なので射影は経度に依存しない）を
`project_observer_to_fundamental` で基本面へ射影し、

```
m   = hypot(ξ − x, η − y)          影軸からの面内距離
L1' = l1 − ζ·tan f1                ζ 補正した半影半径
内部 ⇔ m ≤ |L1'| かつ ζ ≥ 0        （閉半影内 かつ 昼面側）
```

いずれかのサンプル時刻で満たせばその極は領域に属する。

### 返し方

- 北だけ属す → `Some(North)`、南だけ → `Some(South)`。
- **両方属す／どちらも属さない → `None`**（閉じない＝捏造しない）。両方属すのは領域が地球全体に近い
  場合で、片方を選ぶ根拠が無い。
- `partial_limit` が `None` のときは `None`。

### 保持と消費

`EclipsePath` に **`partial_limit_pole: Option<EnclosedPole>`** を追加する（pub フィールドの
データコンテナなので追加は加法的）。`path()` が設定し、`EclipsePath::to_geojson` が
`geojson_geometry_with_pole` へ渡す。

**`partial_limit` の値そのものは変えない**（平面リングのまま）。極で閉じた頂点を実体へ焼き込むと、
その辺（極上の ±180 渡り）が新たな「跨ぎ」として数えられ、後段の分割が壊れる。
極は**出力層で閉じるための付帯情報**として持つ。

判定は `partial_limit` が `Some` なら**常に**行う（跨ぎが偶数でも geo 側が無視するので無害。
奇数かどうかの判定を geo から公開しないで済む）。サンプルは経路生成と同じ `sample_interval_seconds`。

## 完了状況（2026-09-15・strict）

**完了**。極を囲む部分食域が地球を一周する多角形になる欠陥を解消した。

### 実装

| 層 | 内容 |
|---|---|
| `umbra-geo` | `EnclosedPole { North, South }` ＋ `GeoPolygon::geojson_geometry_with_pole`。極を囲む外環を子午線→極→反対の子午線で閉じる（挿入は極の 2 頂点のみ） |
| `umbra-eclipse` | `EclipsePath::partial_limit_pole` を追加。部分食域の定義を極点に適用して判定し、`to_geojson` が geo 側へ渡す。`partial_limit` の値自体は不変（平面リングのまま） |

### テスト設計者の指摘で結線規則そのものを是正した（重要）

当初実装は「両端が同じ子午線に載る弧は自己閉じ」としたが**誤り**だった。子午線の結線が許されるのは
その区間が**内部**のときだけで、内外は弧の帳簿ではなく**極から数えたパリティ**で決まる。誤った規則は
外部の帯を内部として塗り、同時に内部の帯を落とす（3 跨ぎ fixture で面積 6330 対 正 6102）。指摘には
**台形積分による独立オラクル**（cap 面積 = 6102）が添えられ、私の導出が誤りだと確認できた。

正しい規則は偶数跨ぎと奇数跨ぎを**統一**する: 子午線上の端点を緯度昇順に並べ、極を囲むならその極側に
極を挿入してから隣どうしを対にする。極を囲まない場合は `lat=−90` が外部なので下から (1,2),(3,4),… が
内部区間となり §11.8(b) の従来規則と一致する。副次的に、本規則は**リングの向きに依存しない**ため
(3g) の経度連続化による向き判定（`unwrap_longitudes`）が不要になり、死コードとして削除した。

### 残る近似（誤差を隠さない・accuracy §4.3 / conventions §12 に登録）

**ユニオン自体は平面フレームのまま**である。極を囲む日食では平面の even-odd・pip・shoelace が本来
意味を持たないので、**外周位置の誤差は ballpark よりさらに緩い**。本 issue が解いたのは「存在しない辺の
除去」であって、ユニオンの妥当性ではない。精度の表明は据え置く。
